Design System · Kleinanzeigen · 2024

Scaling a Multi-Platform Design System for Millions of Users

Context

Design systems are not just UI libraries — they are a way to align teams, reduce friction, and improve how product decisions scale. At Kleinanzeigen, I work on the design system as the shared foundation for consistent, scalable, accessible product experiences across Android, iOS, and web — used by multiple product squads shipping in parallel.

The challenge

When I joined, the system had grown organically alongside the product. Components existed in multiple versions across platforms, token naming was inconsistent, dark mode coverage was incomplete, and there was no clear model for how teams should contribute or when they should deviate.

The deeper problem wasn't missing components — it was that there was no operating model. No agreed process for deciding what goes into the system, who reviews it, or how platform-specific needs get resolved without creating new fragmentation.

My role

Senior Design Ops / Design System Designer. Working across three things simultaneously: evolving the component library, restructuring the token architecture, and building the governance and contribution processes that give the system longevity.

What I drove

  • Token architecture — Restructured the token layer into semantic, tier-based naming that maps cleanly to both Figma variables and code.
  • Component specs — Established a documentation standard: every component ships with full anatomy, state coverage, dark mode specs, accessibility requirements, and usage guidance.
  • Dark mode & accessibility — Moved both from afterthought to first-class requirement in the contribution process.
  • Contribution model — Built a lightweight governance process for product teams to propose, review, and graduate components.
  • Design–engineering alignment — Established regular syncs with front-end leads and a shared decision log for non-obvious choices.

Reflection

The hardest part of design systems work is not designing the components — it's designing the system around the system: the naming conventions, the decision-making process, the documentation culture, the way you handle disagreement between platform teams. The components are visible. The infrastructure that keeps them consistent is not, and that's where most of the long-term leverage lives.
